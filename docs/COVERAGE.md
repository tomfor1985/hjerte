# Coverage and finite question generation

Studio → Coverage inventories the current source editions before requesting additional questions. This is an AI-assisted inventory of the imported documents, not a guarantee of complete EAPC curriculum coverage or learner mastery.

Each extracted page is tracked with segments of up to 12,000 characters; consecutive segments are packed into requests containing up to 48,000 source characters. PDF segments respect citation-passage boundaries. Long pages are never discarded. Missing pages, chapter-range gaps, unreadable text, unreviewed segments, unsupported note claims and unclassified historical questions remain visible. Reading the report is free. Each action explicitly queues at most 1, 3 or 5 work batches; it does not automatically queue questions or continue through the whole library.

The workflow has three separately queued, persistent stages:

1. `Map & verify source content`: Sol proposes source-specific objectives and exact passage IDs. Sol independently checks each objective, its qualifications, source links and missing teaching points. Primary text appears once in each new request; proposed objectives point to the supplied passages instead of repeating their quotations. Passing objectives are retained automatically even when the section is incomplete. At most two repair passes request replacements and missing points while retaining passed candidates; visual/difficult material and the last repair use Astra. Original PDF page images are supplied to both writer and checker when needed. Every source part must still be accounted for before its group becomes fully mapped. Notes require prior source mapping and primary evidence; unsupported claims remain unresolved. Optional notes-location ranges leave other locations unmapped.
2. `Match shared learning objectives`: batches of up to ten incoming objectives are compared against a complete compact global index. Full selected target evidence and testing angles are checked independently before merging. Only earlier IDs can become canonical targets, preventing cycles. Alias records, source evidence and prior audit IDs remain available; merging never raises a canonical ceiling automatically. Ambiguity blocks the match rather than silently creating a supposedly distinct concept. An oversized index fails the request bound; it is never truncated to an arbitrary top-N.
3. `Link existing questions`: batches of up to ten published, unclassified questions are matched to confirmed objectives. A second model checks actual question scope, answers, explanations and selected objective evidence. Only classification fields change. Unresolved links remain visible and are not automatically retried against an unchanged question/catalogue. Each request still fits the global allowance and the explicit per-job NOK cap.

All inventory models use high reasoning. A job has an explicit NOK cap (25 NOK default), including checks and repairs, and cannot exceed the existing total allowance. Completed work is reused; another user-queued job can retry held content without manual clinical approval. A paid passage draft from the preceding workflow can be reused only with matching source hashes, segment IDs, evidence text hashes and valid references, and always receives the current independent check. Current proposals and each review remain in the audit. Unknown provider outcomes are not retried automatically. No job automatically starts another chapter or generates MCQs.

Stable instructions and, for matching jobs, the compact catalogue are placed before variable request content with explicit cache breakpoints. Changing source/question text is outside the cached prefix. API usage records cache reads, cache writes, reasoning tokens and service tier. Settlement uses reported cache rates when available, with conservative accounting if the breakdown is missing. Reservations still use the worst configured standard price and include uncertain calls; deploying this does not refund or reprice historical records.

Objectives are shared across documents. Evidence retains chapter, source edition and page references; mapping audits retain source hashes and exact proposals/reviews. New editions are separate sources. Retiring an evidence source removes its questions from future sessions and invalidates dependent note inventories. Existing attempt snapshots are never rewritten by classification.

## Duplicate file formats

Prefer PDF when a Word or PowerPoint file and its PDF export contain the same edition. Unique non-PDF documents remain available. Matching filenames suggest a pair in Source setup; an administrator explicitly confirms the pair with `Use PDF as the main copy`. Matching names alone never merge documents, and different editions remain separate.

The alternate file is retained under `Alternate formats retained for history`, with its original pages, hashes, mapping audits and question links. Only the main file appears in new mapping/generation selectors and document coverage totals. Existing questions and attempt snapshots are unchanged. Earlier Word section mappings are not relabelled as PDF page mappings; the objective catalogue remains available for reuse during later mapping. Linking copies does not make an API call.

`Use this file separately again` reverses the link without reimporting. Retiring the main source later also retires its alternate formats and related questions, preserving attempt history. For an explicitly identified existing pair, `prefer_pdf_copy --copy ID --main PDF_ID --user ADMIN` applies the same validated, idempotent operation as the UI; migrations contain no library-specific source IDs.

## Generation rules

- The selected chapter needs current source-checked objectives, matching and classification of existing published questions. Partially mapped chapters can generate only from objective IDs retained by the current segment versions; other content stays outside confirmed coverage.
- `Increase coverage` selects uncovered, active, supported objectives first, one candidate per objective per batch. Re-plan after each batch and again check the ceiling before publication.
- `Add useful variants` is blocked while any mapped, actionable objective remains uncovered. Unmapped material is still visibly excluded from the denominator; mapping the rest of the library should take priority over adding depth.
- The default ceiling is one. Two or three require a recorded useful testing angle. Three is a database-enforced maximum. Reusing an objective from another document does not automatically raise its ceiling.
- Published questions count across all active source documents. Selected notes restrict targets to the objectives verified from those notes.
- Both generator and rationale reviewer compare the entire existing bank, including quarantined drafts, plus the current batch. Structural near-duplicates are screened locally across documents and within the batch. Semantic novelty and exact objective alignment are required in addition to blind-answer and rationale agreement.
- Two unsuccessful attempts pause an objective for review. This is an unresolved objective, not completed coverage. Empty generation results consume requested slots; there is no endless attempt to reach a requested count.
- Incorrect learner answers affect practice scheduling, not generation quotas.

Source/context bounds and the existing API allowance fail closed. Very large catalogues can exceed the conservative request bound; no last-N truncation silently weakens duplicate checks. An index/retrieval design will be needed before that limit becomes a bottleneck.

## Cost interpretation and model change

Question-production estimates use settled token costs divided by published questions, including failed candidates. Uncertain reservations stay separate and are never automatically refunded. Jobs are counted once rather than once per joined API call. Mapping cost uses only measured calls from the current inventory workflow. Later matching/linking costs are shown separately, so the source-reading estimate cannot be mistaken for the cost of all three stages. The page also reports provisional cost per confirmed objective and reported cache/reasoning usage. Rates are unavailable until calls have been settled. While material remains unmapped, the missing-objective count and question-production estimate are explicitly partial. Basic coverage and useful depth are alternative totals, not additive budgets. The optional upper figure is a 50% planning reserve, not a confidence interval or guaranteed ceiling.

After the initial pilot, Terra is the default question generator, with Sol performing separate blind and rationale checks with high reasoning. Studio provides independent writer (Terra, Sol, Astra) and reviewer (Sol, Astra) choices, saved with each queued job. Coverage offers a free price comparison without queuing work or changing defaults. Sol is the default inventory mapper and matcher, with Sol reviewing each stage; bounded inventory repairs can escalate automatically to Astra. Same-model checks can share systematic errors; the source and quarantine gates remain necessary. No new paid calls are made merely by deploying this feature or opening Studio.

The pilot's 50 published questions cost an estimated 78.8398 NOK: 65.7561 for Astra generation, 6.4074 for Sol blind checks and 6.6763 for Sol rationale checks. Repricing exactly the same token use and yield with Sol as generator gives approximately 39.3861 NOK (0.7877 per published question). That is a scenario, not a measured Sol-generation result. With Terra generating and Sol verifying, the same-token scenario is approximately 28.40 NOK (0.57 per published question). Terra generation has not yet been evaluated on a paid pilot. The forecast distinguishes historical costs from this current-model scenario and recalculates it from the call ledger. New prompts, token usage, overlap checks and rejection rates can change the actual result.

The 200 NOK authorization is unchanged. No automatic top-up, no paid retry after an uncertain API result, and no spending from the local ledger. Production remains the sole authoritative allowance ledger.

Answer choices already shuffle independently for every new session. Stored choice order remains stable on reload, resume and feedback; grading maps the displayed position to the original answer. A test now explicitly checks different session orders and stable resumed feedback.

## PDF reading and exact passage citations

The first inventory pilot on 6 September stopped after one Terra call (0.7894 NOK): 41 of 44 model-written quotations did not exactly match the stored layout text. Two PDF columns were interleaved, some table wording was assembled, and the model also reported unresolved cross-references. No objective was accepted and no reviewer or later stage was called.

`inventory-3-passages` adds a separate, persisted `PageReading` layer. Poppler text blocks are ordered by column/band and retain their page coordinates. Every extracted word, short cell label and footnote is retained. XML-forbidden font characters become explicit unknown-glyph markers; affected passages cannot be accepted as citations. This does not interpret diagram arrows or establish table semantics automatically.

Original PDF bytes, `SourcePage.text`, question references and attempt snapshots are untouched. Reading views record the source-file hash, original-layout hash, derived-text hash, extractor version and bounded passage offsets/coordinates. An existing reading view is not silently overwritten. A file/hash mismatch or a stale view stops preprocessing. Preparation is free, idempotent and happens on PDF import or before mapping; the explicit command is `python manage.py prepare_pdf_reading --source ID` with no active AI jobs.

The model selects short passage IDs and section labels. The server supplies the exact quotation, full reading hash and passage offsets. Mapping and MCQ generation from prepared PDFs both use this route. Unknown/unsupplied IDs, changed numbers or offsets, unreadable glyphs and stale views fail source validation. The independent model still judges clinical support, completeness, scope and table/figure relationships. Exact copying alone never authorizes an objective or question. Invalid paid proposals are retained before citation validation, without treating them as reusable approved drafts.

Every source part must still be accounted for. A plain pointer to an absent section/table can be recorded separately when the reviewer confirms that all claims actually stated here have been covered. It does not mark the target mapped. Missing information needed to interpret a present claim still blocks approval. Notes cannot use this mechanism to evade missing primary evidence. These pointers and reading problems are visible in the inventory report.

New views have their own segment content hashes. Prior segment records remain available as history; their coverage is not silently relabelled. An earlier blocked inventory requires an explicit retry after the reading view changes. Once that retry passes, subsequent runs reuse the new mapping while retaining the original failed audit. Cost forecasts use measured calls from the current prompt version; all earlier spending remains in the overall ledger.

Local verification covered all three preferred PDFs (264 pages, 11,654 positioned passages) and checked all 241 citation passages in the original seven-page pilot chapter. The new source text contains 28,787 characters; the compact writer request body is 44,407 characters including citation IDs and coordinates. This is a technical, unpaid check, not a clinical evaluation, a measured API saving or complete-curriculum coverage. Several pages contain unreadable font glyphs and remain explicitly identifiable. Tests cover real two-column PDF extraction, unknown citations, changed/stale evidence, cross-reference checks, missing note support, failed-draft retention, long passages, retry gates and unchanged attempt snapshots.

Before rollout: back up production, ensure no AI jobs are active, apply migration 0009 and run the required checks. Do not copy the local database to production. After explicit deployment/retry approval, prepare the selected source and retry the failed pilot within the unused portion of its existing aggregate 50 NOK cap (49.2106 NOK after the first call). Keep the 200 NOK allowance unchanged. Stop again on unresolved evidence or an uncertain API call; do not automatically start other library jobs.


## Automatic inventory, version 4

`inventory-4-automatic` separates supported candidates from section completeness. New objectives have an idempotent inventory key, preserving IDs across retries. `CoverageSegment.partial` explicitly means that useful checked objectives exist while coverage gaps remain. The first check is followed by at most two repair/check pairs. Repairs are additions/replacements, not regeneration of already passing candidates. A budget stop preserves accepted objectives and any paid proposal awaiting review. Schema omissions, changed evidence and uncertain API failures remain stops. Reconciliation and MCQ verification are still mandatory; model agreement is not proof of medical correctness.

`pdf_images.py` stores versioned 2000-pixel page renders under private source storage, keyed by original PDF hash. Image metadata and hashes are retained with visual references. The original PDF and rendered bytes are verified before use; altered images or editions cannot reuse approval. Visual evidence follows into objective matching, question writing, blind answer selection and rationale review. Source text with unknown glyphs is not repaired by guessing; independently interpreted figure evidence must be tied to original images and valid supporting passage references.

The installed OpenAI SDK exposes `responses.input_tokens.count`, including image/text/schema input. Image requests use that model-specific count plus a 10%/2000-token reservation buffer, with standard-price/cache-write bounds before generation; missing counts stop the request. No guessed image-token multiplier or automatic standard-tier retry is used. Returned usage settles the existing ledger. Local generation remains disabled.

The previous seven-page pilot cost 3.0751 NOK and produced 16 candidates, of which 14 received positive individual Sol checks, but none entered the old all-or-nothing inventory. This is not a measured clinical accuracy score. The new workflow can reuse that paid draft subject to unchanged evidence and a new, stricter item-level check. Apply migration 0010 only after backup; verify existing questions, original sources and historical attempt snapshots after rollout. A bounded evaluation uses the remaining previously approved allowance and does not start further library jobs.
